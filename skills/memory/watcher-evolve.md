# Watcher Evolve Skill

**Auto-invokes when:** the user says "evolve watchers", "do we need a new watcher",
"check instincts for gaps", "generate watcher", or after a session with many
uncaptured Bash failures. Also invokable via `/memory instinct evolve --kind watcher`.

---

## What this skill does

1. Reads the current instinct list to find high-confidence Bash patterns
2. Reads the active watcher list to find what is already covered
3. Judges whether any pattern has enough signal to warrant a watcher
4. If yes: generates a watcher plugin and writes it to `~/.config/crisp/watchers/`

You are acting as an **observer** that reads the project's behavioral history and
decides whether memory capture has a gap worth closing. Do not generate a watcher
unless the evidence actually supports it.

---

## Step 1 -- Read instincts

```
crisp instinct list
```

Look for entries where:
- `tool` is `Bash`
- `command_prefix` is something other than `git` (already covered) or a generic
  utility (`cat`, `ls`, `echo`, `cd`)
- `confidence` >= 0.6
- `count` >= 5 (seen at least 5 times -- enough to be a real pattern)

Note the `command_prefix` values that pass this filter. These are candidates.

---

## Step 2 -- Read active watchers

```
crisp watchers list
```

Note which tool+prefix combinations are already covered. Cross off any candidates
from Step 1 that are already handled.

---

## Step 3 -- Judge

For each remaining candidate, ask:

- **Is there a decision or lesson attached to this command?**
  A `docker build` failure is a lesson. A `grep` call is not.
- **Would missing an episode from this command cause context loss?**
  A `pytest` run that fails and is never captured means the next session has no
  record of what broke and why.
- **Is the command frequent enough that noise is a real risk?**
  If it appears 50+ times and is always successful, a watcher would produce
  50 low-value episodes. Skip it.

If a candidate passes: generate a watcher.
If none pass: report the gap analysis and stop. Do not generate empty watchers.

---

## Step 4 -- Generate the watcher

Write a Python file to `~/.config/crisp/watchers/<name>_watcher.py`.

Template:

```python
"""<Name>Watcher -- <one line: what it captures and why>.

Generated by watcher-evolve skill on <date>.
Review before the next session loads it.
"""

from datetime import datetime, timezone
from lib.store import MemoryEpisode


class <Name>Watcher:
    name = "<slug>"
    tool_names = ["Bash"]

    def matches(self, tool_name: str, inp: dict, out: dict) -> bool:
        cmd = inp.get("command", "").strip()
        # <explain the filter in a comment>
        return cmd.startswith("<prefix>") and <condition>

    def episodes(
        self,
        tool_name: str,
        inp: dict,
        out: dict,
        session_id: str,
        project_root: str,
    ) -> list[MemoryEpisode]:
        cmd = inp.get("command", "").strip()
        exit_code = out.get("exit_code", 0)
        stderr = (out.get("stderr", "") or "")[:600]
        stdout = (out.get("stdout", "") or "")[:400]
        failed = exit_code != 0

        ep_id = f"<slug>_{datetime.now(timezone.utc).strftime('%Y%m%d_%H%M%S')}"
        return [MemoryEpisode(
            id=ep_id,
            session_id=session_id,
            timestamp=datetime.now(timezone.utc).isoformat(),
            layer=0,
            title=f"<prefix> {'failed' if failed else 'ok'}: {cmd[:60]}",
            content=(
                f"# {cmd}\n\nExit: {exit_code}\n\n"
                + (f"```\n{stderr}\n```" if stderr else stdout)
            ),
            source_type="bash",
            source_path=project_root,
            category="failure" if failed else "<slug>",
            importance=0.8 if failed else 0.5,
            frustration_score=0.6 if failed else 0.0,
            tags=["<slug>"] + (["failure"] if failed else []),
            context_snapshot={"exit_code": exit_code, "command": cmd[:200]},
        )]
```

Rules for the generated code:
- `matches()` must be precise -- narrow enough that successful boring calls are
  excluded, broad enough to catch the meaningful ones.
- If failure is the only signal (e.g. `make` always fails for interesting reasons,
  success is noise), gate on `exit_code != 0`.
- Add a comment in `matches()` explaining the filter logic so the user can review it.
- Keep `episodes()` under 40 lines. One episode per call is almost always right.
- Never import from `hooks.py`. Only `lib.store` and stdlib.

---

## Step 5 -- Verify and report

After writing the file, confirm it is valid Python:

```bash
python3 -c "import importlib.util; spec = importlib.util.spec_from_file_location('w', '<path>'); m = importlib.util.module_from_spec(spec); spec.loader.exec_module(m); print('ok')"
```

Then report:
- What instinct pattern triggered the generation
- What the watcher will capture (and what it will skip)
- The path it was written to
- Any concern about noise or false positives the user should review

Do not commit the file or load it. It becomes active on the next session start.
The user should review it first.

---

## When NOT to generate

- The pattern is already covered by a built-in watcher (git, file_change, bash_failure)
- Confidence < 0.6 or count < 5 -- not enough signal
- The command is a pure read (grep, cat, ls, find, curl GET) with no side effects
  and no failure mode worth capturing
- The command is always successful -- success episodes from this tool would be noise

In these cases, report the gap analysis and explain why no watcher was generated.
The user can always ask again after more sessions accumulate signal.
